# Learning setup

Reuse relevant answers already given in this conversation and saved profile. Ask only what matters for the current task, one short question at a time. If the user wants to skip setup, use the defaults below, record unknowns as Not specified, and begin the task.

For an existing project, inspect its entry points, dependencies, storage, integrations, and existing design documents. Make project-map.md a concise orientation with links and verified facts. Ask about the user's familiarity with the codebase only when unknown. For a new project, record proposed choices as proposed.

Keep overall programming experience separate from familiarity with the current stack. Accept per-technology levels; an experienced Python user may need React fundamentals. Use any known goal; otherwise ask what they want to understand or improve. Use intermediate explanations when experience is unknown, adapting per topic; this default is not evidence of demonstrated ability.

Initialize defaults from the [profile template](templates/profile.md). When the user wants customization, offer:

- Checkpoints: Light, Normal, or Frequent.
- Question style: Open-ended, Multiple choice, or Mixed.
- Implementation: AI writes, A mix, or More hands-on.

Use an available native choice tool or concise plain-text options; wait for the user's answers. Teaching and implementation behavior comes from behavior.md.

Save known preferences and goals with state-templates.md. Keep Onboarding: incomplete and a short remaining list while setup is unfinished. Mark complete when finished and remove any Onboarding reset: pending marker. A reset begins fresh: use answers given after reset and current project evidence, without restoring old learning claims from backups or the earlier conversation.
