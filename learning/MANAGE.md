# Manage project learning

New projects keep learning off until explicitly enabled. Save natural-language enable/resume/off/pause requests as exactly one unformatted `Learning mode: active` or `Learning mode: paused` line in profile.md. The choice survives tasks and conversations in the same checkout. Apply only the requested control or preference changes; a mode change alone does not reopen an agreed design.

For a new explicit reset request, read [PRIVACY.md](PRIVACY.md) and use [RESET.md](RESET.md) before changing controls or other notes. Use the reset preview's selected path to enforce privacy before resetting; a normal inspection error does not block this explicit recovery path. After reset, continue below with the preserved mode.

1. Run the read-only helper from [the entry guide](LEARNING.md). Use its selected path, profile_status, and Git tracking result; legacy notes stay in place. On an error, explain and pause this entry workflow until the issue is addressed or the user explicitly chooses to proceed without learning. Done when the selected directory and effective mode are known.
2. Before any note writes, read [the privacy guide](PRIVACY.md) and resolve private_notes_tracked there. Apply explicit control changes first; otherwise honor the saved mode. On explicit enablement, announce a new directory and create only missing notes from [the state templates](state-templates.md), preserving existing companions. A pause in a new project needs only a minimal paused profile with incomplete onboarding. Save requested preferences without changing the mode unless asked. Enforce the notes' tracking choice and rerun the helper after changes. Done when the helper reports the requested controls and permission to write notes is known.
3. When this request enabled learning, explain once: new conversations in this checkout reuse its notes; separate checkouts have separate notes; deleting the checkout or cleaning ignored files also removes local notes and their backups unless preserved elsewhere; learning resumes through planning or implementation rather than activating every new chat. For a request only to change controls, preferences, or tracking, report the saved change and finish before asking setup or design questions.
4. After a successful reset, or if a task accompanies the change, continue under the resulting mode using the entry guide's Off or Active branch directly. An active reset resumes fresh onboarding and rebuilds the map even without an accompanying task; a paused reset remains paused. Preserve an explicitly requested implementation workflow; otherwise read `~/.agents/skills/implement/SKILL.md` for ready-to-build work.
