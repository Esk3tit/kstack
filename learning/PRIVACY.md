# Private learning notes

Learning notes and backups stay out of staging and commits unless the user explicitly chooses to track them. Save that permission in profile.md's `Track learning notes` field; no or a missing field means private, not evidence of an opt-in. If private_notes_tracked is true, suspend note writes and reset until the user chooses tracking or removal from Git's index. Show the reported tracked paths and explain that switching, merging, pulling, or rebasing across the commit that untracks them can overwrite or delete local notes. Other checkouts need their own backup before incorporating that commit; previously committed notes can also be recovered from Git history. Untracking changes future commits and does not erase earlier history.

An explicit opt-out authorizes `git --literal-pathspecs rm --cached -- <tracked paths>`. Before running it, create a fresh untracked directory under the selected notes directory's `backups/`, with its own `.gitignore` from [the privacy template](templates/private.gitignore). Copy the existing tracked files into its `files/` subdirectory, preserving relative paths and checking for links before copying. Verify the copies match and report the backup location; if backup fails, leave the index unchanged. The command leaves local files in place initially, but later Git operations can still remove them. Explain how to restore from the backup and that it cannot preserve later edits. Reinspect after untracking.

For private notes, create a regular `.gitignore` inside the selected notes directory using [the privacy template](templates/private.gitignore), or append its ignore-all rule to an existing regular ignore file while preserving its contents. In Git, also resolve `git rev-parse --path-format=absolute --git-path info/exclude` from the checkout and append an anchored, Git-ignore-escaped rule for the selected notes directory relative to the checkout root. Preserve existing rules and avoid duplicates. This local exclusion survives changes to a previously tracked notes-directory guard. Create guards only when the directory already contains learning notes or is being initialized by an explicit request; ordinary use of an empty or missing directory creates nothing. Check for links before writing; leave the project's root .gitignore alone.

On explicit tracking opt-in, save the choice and use `git --literal-pathspecs add -f -- <explicitly chosen note paths>` when staging them. Retain the exclusions so new notes and backups still require a deliberate add; Git continues tracking files already in its index. Stage only application paths unless the user has chosen to track the notes.

Git cleanup that removes ignored files, such as `git clean -x` or `git clean -X`, also removes these notes and their colocated backups. Preserve anything needed outside the checkout before such cleanup.
